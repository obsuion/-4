# Provenance of the two case inputs

[D1_BALANCED](../examples/inputs/D1_BALANCED.json) and [D2_LIGHT](../examples/inputs/D2_LIGHT.json) are the original, unmodified model input documents from the P64 preparations. They describe independent simulated spacecraft, not flight telemetry. Their exact SHA-256 values match both the preparation report and the archived handoff. For each design, the prepared root identity matches the store identifier in that design's completed event export. A file SHA-256, a model root identity and a Git commit are different identifiers.

provenance.json records the hashes, the shared model-clock interval (128–7,776,128 s), run sizes, and model source bindings. The input documents are portable data, not self-starting jobs or checkpoint images. The original inputs remain useful even where later administrative code extended a run's allowed attempts.

The initial CORE source bundle was frozen under the project identity beginning **ab86407e**. The D1 final review also archived later execution/control manifests. Its control revision 28 differs from the preparation snapshot in sixteen runtime modules. Four relevant science modules — operator execution, geometric observations, physical action checks and product assessment — have exactly the same file hashes in both source manifests. This verifies those files, not the entire executable, and does not identify the exact D2 launcher revision.

D1 and D2 event exports establish what the model recorded; their file hashes are listed so archived copies can be identified. D1 also has a full final summary archive with its CAMPAIGN source epoch. D2's events identify the case plan; the final D2 CAMPAIGN source tree and its final summary archive were not available in the material checked for this release. The historical full application, local services and original Git history are not reconstructed from the scientific input documents. The release therefore does not claim a one-command bit-identical replay of either complete 90-day Windows run.
