# YEAR-V5 strict quiet progress admission

The first actual new-method short attempt was stopped after its parent rejected
the versioned quiet progress method. The failed store and frozen source remain
evidence; that attempt is not a completed mission or coverage result.

The parent now takes the expected quiet method and policy from its trusted
environment/battery/solar root. It does not infer authority from the worker's
method string. Legacy private calls retain the existing exact 22-field work
shape, historical display bounds and optional absent quiet value. The three
explicit YEAR-V5 method identities require an exact matching supported policy,
non-absent work and exactly 41 fields: the 22 legacy fields plus 19 new counters.
Unknown/missing fields are rejected rather than recomputed or ignored.

Canonical displayed rational durations are decoded before reconstructing the
new work record and validating it with `ShortCircuitQuietWork.validate` against
that policy. This retains performed/reserved/returned accounting, first/second
conservation, exclusive early-reason/skipped-call and norm conservation, policy
quota bounds and exact controller limits. Skipped calls are not added to paid
reservations. Method, phase, counters and policy types remain strict. A coherent
set of untrusted counters is still a display declaration, not independent proof
that work occurred or execution permission.

Only Python application admission is changed. The quiet physics/Cython code,
native support closure, selected physical path and frozen old stores are
unchanged. Focused tests use actual work-owner operations without physical
leaves. A routing unit keeps the real root binding and quiet validator while
explicitly isolating unrelated display validators; actual production-runner
acceptance remains a separate required gate.
