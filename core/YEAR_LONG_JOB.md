п»ї# YEAR-V1 authored long job contract

This candidate compiles a supported authored SpacecraftProjectV3 using the
existing paid design compiler. It retains every component, pose, electrical and
thermal declaration, original trajectory anchor, initial state and controller.
Only the declared mission duration changes. DAY=86400 SI seconds;
YEAR=31557600 SI seconds. Preparation is not computed year coverage.

Environment admission requires the existing explicitly ASSUMED annual Sun
model, full-domain nominal world and declared long study. Every old forcing
piece must have exactly the same full payload and match that study. This is an
explicit stationary coefficient law over the requested domain. An old Sun table
is neither extended nor repeated; its original domain is retained in job DATA.
A genuinely varying short forcing profile refuses. This path does not fetch
new ephemerides or assert physical/event-time accuracy.

Producer API: year_project.compile_job(project,duration_seconds,ledger,policy,
build_bytes) -> canonical bounded initial job bytes. year_project.admit_job
reconstructs the actual compiled full root with a paid independent compiler.
create_store uses the real ProjectStore, paid preview and LifecycleWorkspace.
The original/derived project documents, full root, source/runtime/build/policy
bindings, constructor declaration, environment and conditional quotas persist.

Execution remains lifetime_supervisor.run and LifecycleRunner. maximum_segments
bounds an invocation between durably settled segments; it does not change a
physical action, a numerical cell or the root/policy. Resource continuations use
the exact latest settled checkpoint, cumulative state/work and original anchor.
A fresh process must re-admit source, root, project lineage, checkpoint and
runtime. No initial battery, age, orbit or calendar reset is allowed.

YEAR_V1_WINDOWS_AUTHORED_SERIAL_EXPERIMENT is a distinct experimental permission.
It is not LINUX_PRODUCTION, accepted LONG qualification or a certificate of
physical adequacy. Existing bounded PILOT and Linux LONG evidence guards remain.
The experimental policy remains finite: at most1024 primary segments,2 diagnostic
slots and900 hard seconds per segment, with ordinary finite disk/RSS/output and
cumulative ledgers. A prepared job can fail admission for insufficient resources.
No full year is executed by this coding task.

Stop requests the existing supervisor's cooperative operator-pause marker.
A request is not a settled checkpoint. Resume is explicit after USER; automatic
serial continuation is limited to valid RESOURCE_TIME/RESOURCE_OUTPUT. TARGET
means actual requested endpoint; model/domain/process/integrity failures are
not coverage and cannot be silently retried. Status and export remain read DATA.

Exact optimization: full owner-signature construction and historical scientific
encoding are implemented in the bound native metadata loops. Every metadata
field, constructor/function/default/keyword/mro/enum check is retained. Original
reference functions remain differential oracles. No numerical arithmetic, error
bound, physical guard, integration grid, scientific ledger charge or precision
is changed. The helper is process/thread/invocation scoped, nonpersistent, has
no numerical result cache, and cannot turn DATA into execution authority.
Full scientific output equality and actual mission timing are separate gates.
Timing improvement is an empirical result, not promised by this contract.

Current model boundaries persist: supported rigid cuboids and authored poses;
aggregate compatible co-oriented PV, ideal regulated star with one PV and seven
load branches, finite component/route counts and declared lumped thermal roles.
Prescribed external thermal forcing and radiation/exposure ageing are assumptions.
A full inertia tensor is not general three-axis flight attitude dynamics.
This contract does not claim universal CAD, flight qualification or full V5/M.

The production worker keeps metadata scope through checkpoint/report publication,
not only the selected numerical transaction. The serial supervisor likewise
selects it only after strict complete typed contract DATA admission, followed
by unchanged original store/plan/source/project/permission admission. Legacy
workers and stores retain their original route. No old store/source is retagged.
