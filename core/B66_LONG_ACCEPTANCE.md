# B66 per-design LONG evidence admission repairs

This contract tightens the existing B65 genuine typed evidence V2 reader. It
does not migrate old stores, change scientific inputs or grant Linux readiness
to a Windows result. Genuine target execution and all existing source, runtime,
build, process-fixture, restore-watch and scientific endpoint gates still apply.

Before producing PASS or `acceptance.json`, the producer recomputes
`lifetime_execution_authority.domain_identity` independently from each actual
reference, native baseline and native continuation root. Each must equal the
requested binding. The sole horizon exclusion remains `inputs.duration_seconds`
and its envelope digest; original anchor and all other model, hardware,
numerical, controller, quota and source/build/runtime pins remain authoritative.
Mutually equal histories for design A do not qualify a requested design B.

The historical field `native_uninterrupted_store` is retained for compatibility.
Its precise B66 meaning is an independent complete serial native baseline;
legitimate resource-bounded serial resumes are allowed. The separately tested
continuation must resume from a substantive retained checkpoint in a fresh
owned execution and agree scientifically. It must not be the baseline history
compared with itself, including when a completed store was copied to a new path.

The producer re-reads each causal segment's immutable request, parent launch
authority, backend settlement and settled owned receipts. It checks job, root,
source, runtime, request hash, dispatch owner, worker identity, private process
owner and checkpoint ancestry. The reference, baseline and continuation terminal
job/dispatch/private-owner identities must each be absent from every segment of
the other comparison histories. A continuation may share an authentic earlier
checkpoint prefix; its terminal execution must still be independent. PIDs alone
are not uniqueness authority because an OS can recycle a PID. This validates
declared durable provenance, not hostile-system attestation.

The new metadata-only unit regressions exercise the actual domain and durable
provenance readers, including copied stores, per-root mismatches, fresh receipt
reads, serial baselines and shared authentic prefixes. Their scientific terminal
and target-platform validators are explicit test doubles. They are not actual
Linux day execution or physical qualification evidence.
