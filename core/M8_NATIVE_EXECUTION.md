# B63 prepared/native execution contract

This is an uncommitted M8 implementation candidate over the complete B62
754-file source. It does not complete Version M, the long-run qualification,
or full V5. The delivery report and saved evidence, outside this source tree,
state actual gate outcomes. Native compilation alone establishes no speedup.

## Execution identities

`B54_FROZEN_INPUT_ADMISSION_V1` remains static input admission.
`B60_SEALED_STATIC_V1` remains the bounded static cache strategy. Neither name
means compiled numerical execution. B63 separately selects `REFERENCE`,
`PREPARED_PYTHON`, or `PREPARED_NATIVE` under `B63_PREPARED_NATIVE_V1`.

The new V2 policy, initial package, execution contract and store formats are
distinct from B62. `lifetime_source.SOURCE_PATHS` retains the old 754-member
producer; `B63_SOURCE_PATHS` declares this producer. Old result DATA remain
readable. Read-only inspection never grants permission to execute or migrate
an old native checkpoint.

PILOT authority binds exact input/root/domain, source, runtime, policy, backend
and build. It is limited to 86,400 simulated seconds, eight primary segments,
two diagnostic slots and 240 wall seconds per child. LONG requires genuine
bound acceptance evidence and production runtime admission. A manually set
flag, doctor result alone, missing portable contract or a generic legacy
store cannot authorize long execution. Common gates precede public intent
writes, claims, reservations and worker fallback.

## Static and dynamic ownership

Preparation fully admits an independently reconstructed input and model and
owns its frozen topology, thermal/routing/electrical policies, units, frames,
mounts, tensor references and provenance. ACTUAL and received-FORECAST have
separate runtimes, caches and operational ledgers. No process-wide function
replacement activates a backend.

External and owned static graphs remain sealed at public boundaries. The
established derived `_identity` refresh and exact canonical
`ComponentAxisBinding.local_axis` refresh are checked by exact built-in value
and type; this does not permit a changed authority or numeric coercion.
Backend activation, actual compiled callables, source/runtime/build and role
wiring are checked independently. Changing `native` or `selection` cannot
silently turn a declared native run into a Python fallback.

The service adapter copies already paid construction/hardware outputs once
per role, without recompiling or resetting their scientific ledgers. Its
per-leaf same-type context shell forwards only the current dynamic state;
numeric configuration comes from owned static copies. No energy, temperature,
history, completed forecast, request, transfer or outcome is cached as static.

An eight-entry exact history cache shares each current epsilon/G/PV
realization between thermal and quiet metrics. Keys include exact types,
values, signed zero and provenance. History advances only for selected cuts;
rejected full/half trials retain paid work and publish no ageing state.

## Input admission and projection extension

The measured residual profile motivated an explicit invocation-local input
codec for prepared selections. It retains original typed leaf encoders,
decoders, constructors and normalization roundtrips. Full registry/owner
seals are checked at entry and finally-exit, including unused owners; strong
references prevent metadata identity reuse. Every used owner is checked,
operational work is finite, and failures retain paid work and primary errors.
REFERENCE retains the original reader. The codec supplies DATA admission,
not native activation, a checkpoint, execution authority or cached truth.

Owned service comparands are built once and sealed; incoming values and
current dynamic state still pass exact checks. The eight-entry history cache
also supplies full fresh environment projections with exact history and
provenance keys. Actual and forecast caches remain separate. Untrusted saved
readers and remaining offer/seal validation retain the reference path.
These Python preparation changes do not imply a changed numerical method or
prove an end-to-end speedup; final source-bound evidence decides that claim.

## Numerical owner

The optional compiled owner contains the actual service allocation/bisection,
wire calculations, battery R/V/I and energy/heat transition, simultaneous
thermal transition, degradation/reconciliation and guarded private commit.
The full quiet proposal and sequential two-half schedule are compiled too.
CONTACT uses the same explicitly bound service adapter. Original record and
exception classes retain their identities.

The initial native domain requires the declared construction service, battery
port and exposure-ageing owners. Unsupported native admission refuses before
scientific work; it does not retry a half-completed transaction in REFERENCE.
REFERENCE is an explicit selection. Legacy default calls retain their
reference numerical route.

Cython uses Python-object operations, arbitrary Python integers, exact
Fraction values and actual Python `math.fsum`/math calls. No float32,
reassociation, widened integration step, alternative method, discarded fee,
changed rounding rule or hidden state reset is introduced. Compiler flags
disable fast math and FP contraction. Complete exact scientific projections,
refusals, selected cuts and ledgers require comparison; agreement of widths or
temperatures alone is insufficient.

Preparation, copies, failed attempts, cache and backend dispatch have separate
bounded operational receipts. They never replace physical/Picard/quiet,
allocation, ageing, construction, actual or forecast scientific accounting.
Per-invocation operational data and retained parent publication costs are
reported separately from authoritative accumulated model work.

## Status, settlement and storage

New V2 stores publish `B63_BOUNDED_STATUS_ENVELOPE_V1` heads with decoded
record cap **65,536 bytes unchanged**. Immutable details have their own
256-KiB cap, strict schema and content/context binding. Details commit first,
head last. Caller/cache/sequence advance only after durable head publication.
A pure preflight refusal does not poison a writer; failed I/O quarantines it.
Listings read compact heads rather than hydrating all history.

Details and heads each use half the existing status allowance, with reserved
terminal/error capacity. Actual hashing, codec, metadata, reads and failures
remain charged. An independent bounded error channel preserves primary,
secondary-close and callback failures. A terminal callback cannot rewrite an
already committed scientific outcome.

Application settlement and OS ownership are different claims. A matching
dispatch token is released only with confirmed private-Job/group cleanup,
reaped root, captured exit status, closed handles, no cleanup error and the
absolute deadline gate. Missing `launch` is not proof of cleanup. Unsaved or
uncertain application state blocks further scientific dispatch even if OS
cleanup succeeded. Close attempts all resources best-effort.

The shared pool V2 credits only software-owned, bound, canonical immutable
files. Foreign/padded/unattributed data earn zero credit or refuse admission.
Overlapping roots, hardlinks and portable-path aliases are refused. STORE,
initial package, export and backup roles retain their full prospective
reservations. Logical credit is separate from physical allocation; unknown,
sparse or compressed physical allocation earns zero physical credit. There
is no deletion or quota refund.

## Checkpoints and cooperative Stop

The old V8 reader retains its exact schema. B63 uses a distinct
`B63_PREPARED_EXPOSURE_EXECUTION_CHECKPOINT_V1` wrapper over the same known
physical graph schema, with explicit backend/source/runtime/build binding.
Preparation and caches are reconstructed; authoritative dynamic state and
paid model work are restored directly. No causal prefix is replayed to warm
the backend. MAIN/loupe require exact same-source/build/runtime authority;
Windows native checkpoints are not implicitly migrated to Linux.

The public B63 worker reserves the existing restore control allowance before
`prepare_checkpoint_restore` performs the original full static backend
admission and known-owner DATA materialization in ADMISSION. Original-anchor
gravity validation remains present and paid there. The separately watched
RESTORE then consumes a single-use, same-process token owning that exact
decoded model and context; root, PID, runtime, source/build, checkpoint bytes
and bindings are pinned, and the strongly retained graph is sealed before
consumption. Raw/header admission and all original restore guards remain.
Preparation and RESTORE share the unchanged control allowance, including
failed attempts; scientific fees and quotas do not change. Successful
transfer releases the token's graph and seal. This transient ownership is
neither a persistent cache nor a checkpoint authority. Preparation and
RESTORE native-entry proofs are distinct; the original Python watch is not
suppressed. Legacy calls without a token retain their original restore path.

The compiled module exposes detached DATA from a private monotone entry
monitor for 17 numerical owners, charged before their guards and retained
after exceptions. Its PyLong counters have no public reset and refuse on
saturation. Direct native restore binds before/after snapshots to the actual
extension receipt and requires every delta to be zero. This complements the
separate original-Python code-event watch; a producer's assertion alone is
not independent evidence of zero prefix work.

For deterministic short PILOT verification only, `store.arm_pilot_stop(jid,
minimum_partial_bits)` can publish a strict immutable rule before owned
launch. The sole rule tests a returned committed pending CONTACT and one
actual partial record at the threshold; it never sums records or invents a
cut. It requests the existing cooperative Stop/checkpoint path and saves a
bound trigger receipt. The numerical input, method, physical partitions and
controller remain unchanged. This avoids relying on a parent polling sleep.

## Build and evidence

`lifecycle_native.pyx`, generated `lifecycle_native.c` and
`lifecycle_native_build.py` are the reproducible build sources. The local
build takes explicit isolated compiler and Cython directories and downloads
or installs nothing. Its receipt binds actual artifact bytes, compiler/flags,
Python ABI/runtime, source and executed capability screen. The ABI-specific
binary is not a portable Linux qualification claim. Target Linux build/day,
year and 15-year campaigns remain separately gated.

The representative benchmark compares the same frozen roots and scientific
policies with normal B60 FAST on both sides. Worker application end-to-end
timing includes per-run prepared admission, actual and received forecast,
materialization, records/report, checkpoint and writer settlement. Production
parent/OS settlement is verified separately; it is not fabricated in a warm
worker benchmark. Every pair, cold/warm cost, CPU/wall sample and failure is
retained. Only a complete declared gate may establish 15x; otherwise the
delivery report states `PERFORMANCE_TARGET_NOT_MET` or the precise missing
evidence. No kernel timing is extrapolated to H5 or mission lifetime.

All exposure/power/ageing laws retain their existing declared ASSUMED status.
No new hardware campaign, flight calibration or physical lifetime validation
follows from execution. Combined qualification remains UNRESOLVED, H5 remains
unestablished and the historical B7 cause remains UNKNOWN.
