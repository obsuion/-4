# CORE YEAR-V4 review candidate

This candidate keeps the YEAR-V3 numerical model, action boundaries, exact
scientific recording and original-anchor continuation. It is not a new
accuracy-qualified integrator or a physical validation claim.

* P1: explicit process/thread/operation-owned parent admissions, immutable
  current-byte and source/build/runtime rechecks, root/schema/callable seals,
  per-request pins, no persisted token or global cache. Foreign callbacks lie
  outside reusable operation scopes. Fresh reopen/worker remains fully admitted.
* P2: one native fixed job/generation record path replaces repeated Python
  identity, ledger and generation descriptor processing. Full/callback/rollback
  guards remain. Operational record counts are separate from scientific work.
* P3: independent lossless checkpoint frames, default zlib level 3, optional
  stdlib zstd level 3, and bounded RAW fallback. Canonical decoded schema, SHA,
  role and complete root/source/runtime bindings retain authority. Encoded
  receipt hashes are administrative and never restoration permission.
* P4: explicitly versioned physical policy/store. Whole commitment 8522825728
  bytes (7.9375 GiB), including 3 GiB retained, 3 GiB independent backup reserve,
  512 MiB active write, 128 MiB terminal, 128 MiB temporary, 640 MiB export and
  576 MiB index/metadata. The backup is reserved, not created. Failed/unknown
  writes retain their full grant. Only registered closed producer inventories
  earn physical credit; negative directory scans do not establish ownership.
  Global retained exhaustion creates durable HALT without an empty retry loop.
  The local owner admits SQLite3.50.4 with its exact source ID, DELETE journal,
  4096-byte pages and allocation units no larger than4096 bytes. The metadata
  allowance includes the source-derived worst-case rollback-journal formula;
  unsupported runtime/filesystem combinations refuse before disk writes.

LifecycleStore.export and legacy portable-package export refuse physical
stores before IO; use lifetime_supervisor.export_result for a separately
reserved DATA export. Existing stores/policies and identities are not migrated.
Administrative stdout/stderr use bounded draining pipes, not an overshoot-prone
polling-only disk cap. Capture errors or incomplete reader cleanup invalidate
settlement; cleanup shares the existing absolute private-Job deadline.

Durability counters distinguish explicit Python fsync wrappers and logical
SQLite COMMIT from SQLite internal syscalls. OS process IO counters are reported
separately. Directory power-loss qualification on Windows is NOT_TESTED.

Gates and actual timings are recorded outside source in the source-bound review
package; code existence and AST checks do not establish acceptance. YEAR_NOT_RUN.
A smaller finite cap is not a proof of sufficient year capacity. Final 12
research designs are not supplied; this is the existing authored baseline.
