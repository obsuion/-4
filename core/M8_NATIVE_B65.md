# B65 versioned exact native candidate

This is a bounded engine/runtime candidate, not full product or flight
qualification. The final external review package owns measured outcomes.

`B65_TYPED_EXECUTION_V2` uses the existing B64 coupled and quiet implementation.
It adds machine binary64 gravity/J2/RK4 fields and arrays with private per-plan
scratch. The original exact Fraction time decisions, anchor, grid, tail cache,
evaluation order, reservations and atomic endpoint publication are retained.
Python `math.hypot`, `frexp`, `ldexp`, float power and `math.fsum` remain exact
intrinsic barriers. Fast math, contraction, reassociation and C-libm replacement
are forbidden. Inputs outside the pre-admitted exact float/small-int model
conversion domain select the original object RK4 before numerical work; there
is no failure/retry fallback. Returned operational receipts count machine and
reference-world attempts separately; no dynamic ephemeris or physical result
is shared across roles/designs.

The private closed-generation owner is process/thread/job/source-bound and
cannot be copied, pickled or decoded from an input. Outer transactions retain
full schema/graph/closure/build checks; pinned nested internal cuts use cheap
ownership, role, active-generation and counter checks. Foreign callbacks suspend
the capability, force full checks and reject reentrant transactions. Exit,
restore and publication retain full boundary admission. Scientific work is
unchanged. Historical logical boundary prepayments are preserved and identified
separately from new actual full/closed validation counters. A receipt is DATA,
never an execution capability. No energy, thermal, attitude, custody or
knowledge state is cached by this validation mechanism.

The native build has separate strict Windows/AMD64 and Linux/x86_64 profiles
for normal-GIL CPython3.14.7. Cython3.2.4 and target wheels are pinned; compiler,
linker, headers, source/include/generated C and actual loaded extension are
bound. See `kit/README-TYPED-B65.md`. B64 Windows receipt validation is not
broadened to Linux. Historical B64 source/build remains available for direct
comparison, and the current B64 profile can explicitly bind the additive literal
include closure without claiming the new method. Missing native dependencies
refuse; Python never masquerades as native.

New contracts/packages/plans/results use B65 V4 identities, a separate B65
checkpoint wrapper and backend binding, and exact runtime/source/build pins.
Old B63/B64 readers remain. Advanced checkpoints are not migrated or relabelled.
Source membership is finalized once after build and before execution freeze.

The typed server adapter exposes the actual build/capability and versioned
plan family. LONG requires genuine per-design target evidence: process protocol,
full same-runtime reference/native day equality, native uninterrupted/continued
day equality, substantive fresh restore and original-call/native zero-prefix
proof. The producer recomputes saved evidence and accepts no approved flag.
Without an executable Linux target, actual Linux build/day/continuation stay
NOT_RUN, even when detached contract tests pass.

DESIGNS owns hardware compilation outside the engine; CAMPAIGN owns queueing
outside the engine. The external immutable CORE handoff supplies final paths,
source/build/runtime identities, caps, CLI, common assumptions and acceptance
states. Compile initial roots once for that handoff. Independent designs have
independent causal histories. A small pilot, kernel equality or T7200 timing
does not establish year/15-year affordability or continuous physical accuracy.
